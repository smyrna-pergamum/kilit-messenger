# app

Kilit's Flutter app for Android. Windows comes later.

All cryptography runs in the Rust core (`core/crates/kilit-ffi`). The app
never holds a key; it asks the core through `lib/core/kilit_core.dart`.
`lib/core/dev_core.dart` exists only for widget tests and encrypts nothing.

## Layout

| Path | Contents |
| --- | --- |
| `lib/core/kilit_core.dart` | Everything the UI may ask of the core. Keys never cross this line. |
| `lib/core/rust_core.dart` | That interface, bound to the Rust core |
| `lib/src/rust/` | Dart code generated by flutter_rust_bridge (do not edit) |
| `rust_builder/` | The cargokit glue that builds the Rust core for each platform |
| `lib/state/session.dart` | Whether the vault is open or locked. Leaving the app locks it. |
| `lib/state/chat_service.dart` | Keeps the relays connected while Tor is up; a network round every few seconds |
| `lib/state/prefs.dart` | Theme, language, Tor and bridge choice |
| `lib/platform/tor.dart` | The embedded Tor (`libkilittor.so`, see `engine-tor/`) through Dart FFI, and the automatic bridge fallback |
| `lib/platform/pin_key.dart` | The hardware key the PIN is bound to |
| `lib/platform/files.dart` | Picking, saving and sharing files; links and files other apps hand to Kilit |
| `lib/screens/lock_screen.dart` | Creating and entering the PIN. The digits are shuffled every time. |
| `lib/screens/chats_screen.dart` | Chats, adding contacts (QR, link, `@ID`), Requests, a conversation |
| `lib/screens/group_screen.dart` | New group, a group's conversation, group info |
| `lib/screens/camera_screen.dart` | Photos taken from the preview stream, in memory |
| `lib/screens/vault_screen.dart` | The vault, carrier messages, opening pasted text, packet analysis |
| `lib/screens/settings_screen.dart` | Protections, Tor connection and bridges, panic code, language, theme |
| `lib/screens/shell.dart` | Bottom bar on phones, side rail on wide windows; routes what other apps hand in |
| `lib/theme/` | Night blue and brass palette, light and dark |

## Platform hardening

- **Android:**
  - `FLAG_SECURE` blocks screenshots and screen recording.
  - Android backup and device transfer are off.
  - Flutter's `PROCESS_TEXT` query is left out.
  - The only network permission is the one the embedded Tor needs; nothing
    else in Kilit opens a connection.
  - The microphone permission the camera plugin adds is removed, because
    Kilit takes stills only.
  - The package id is `app.kilit.messenger`.
- **Windows:** the window is hidden from screen capture with
  `WDA_EXCLUDEFROMCAPTURE` (Windows 10 2004 and later).

## Languages and settings

- **English is the main language.** New installs open in English, and so
  does any system language Kilit does not have. You can pick another
  language, or "System language", in Settings.
- **15 languages:** English, Arabic, German, Spanish, Persian, French,
  Indonesian, Italian, Japanese, Portuguese, Russian, Turkish, Ukrainian,
  Vietnamese and Chinese (Simplified). Arabic and Persian lay out right to
  left. Translations other than English and Turkish were made by machine and
  need a review by native speakers.
- **Adding a language:** `lib/l10n/app_en.arb` is the template. Add a
  `.arb` file, then add the language under its own name to
  `supportedLanguages` in `lib/state/prefs.dart`. `flutter gen-l10n`
  generates the Dart code. `test/app_test.dart` opens the lock screen and
  Settings in every language and checks that nothing overflows.
- **Preferences:** theme, language, the Tor switch, the bridge choice and
  the clipboard hint are not secret. They are needed before the vault opens,
  so they live in `prefs.json` beside the vault. The panic code resets them,
  except the language.

## Links and files from other apps

- **`kilit://add?…` links**, whether opened from a browser or chat, or
  found inside shared text, open the add-contact sheet with the link filled
  in. Adding someone still takes a tap, so a web page cannot add contacts
  unseen.
- **Files:**
  - On Android, files are read and written as streams through the Storage
    Access Framework (`FilesChannel.kt`). Unlike ready-made picker plugins,
    this leaves no plaintext copy of the chosen file in the app's cache.
  - `.klt` files and `KLT1:` messages shared from other apps go to the vault
    once it is open.
  - Android has no reliable way to match the `.klt` extension, so Kilit also
    offers itself for untyped binary files, and opens one only if it starts
    with the `KLT1` magic.
- **Limits:** a vault file can be up to 64 MB, a file sent in a chat up to
  5 MB. Saving a file unencrypted always asks first.

Font: JetBrains Mono (OFL), shipped with the app, for codes and
fingerprints. Everything else uses the platform's font; no font is
downloaded.

## Building and testing

```bash
./repro/build.sh android
```

That builds the image once. Then:

```bash
docker run --rm -v "$PWD:/src" -w /src/app kilit-android sh -c 'flutter analyze && flutter test && flutter build apk --debug'
```

The embedded Tor is built separately, before the APK (see
`engine-tor/README.md`).

When `core/crates/kilit-ffi/src/api.rs` changes, regenerate the bindings.
The image pins flutter_rust_bridge_codegen 2.13.0 and cargo-expand 1.0.127:

```bash
docker run --rm -v "$PWD:/src" -w /src/app kilit-android flutter_rust_bridge_codegen generate
```

**Release APKs** are built unsigned (`flutter build apk --release`), then
aligned with `zipalign -p 4` and signed with `apksigner` using the release
key. The key never enters the repository, and the CI fails if signing
material is ever tracked.

The Windows app cannot be built in Docker. On Windows, use Flutter 3.47.7
and Visual Studio's "Desktop development with C++" workload, and run
`flutter build windows`.
